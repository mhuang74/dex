# Review Phase Resilience v2 — plan-review.md

## Problem

When LLM provider usage limits are hit, the agent process stays alive but stops producing output. The `Runner` kills it with `"agent idle timeout"`. Re-running `dex review` starts from scratch — all completed reviewer work is lost.

The v1 spec (`review-resilience.md`) proposed session tracking, `review-progress.json`, `--resume` flag, `ResumeMode`, and fixer session resume. This v2 spec takes a simpler approach: **make `review` work like `apply`**.

## Key Insight: `apply` Already Solved This

The `apply` (implementation) phase uses `plan.md` as a persistent task list with `- [ ]` / `- [x]` checkboxes. `impl_phase` calls `next_open_task()` to find the first incomplete task. Re-running `dex apply` naturally picks up where it left off — no `--resume` flag needed.

`review` should work the same way: a `plan-review.md` with checkboxes tracks progress. Re-running `dex review` reads the existing plan and skips completed steps.

---

## Changes

### 1. New file: `.dex/plan-review.md`

Generated by dex from `reviewers.json`. Uses the same heading + checkbox format as `plan.md`, so the existing `plan.rs` parsing functions (`parse_plan`, `next_open_task`, `plan_step_counts`) work without modification.

**Example** (3 broad reviewers, 2 focused reviewers, 3 focused rounds):

```markdown
<!-- base_ref: abc123def -->

## Broad Review
- [ ] quality
- [ ] security
- [ ] performance

## Broad Fixer
- [ ] fix broad review findings

## Focused Review — Round 1/3
- [ ] critical-correctness
- [ ] critical-coverage

## Focused Fixer — Round 1
- [ ] fix focused round 1 findings

## Focused Review — Round 2/3
- [ ] critical-correctness
- [ ] critical-coverage

## Focused Fixer — Round 2
- [ ] fix focused round 2 findings

## Focused Review — Round 3/3
- [ ] critical-correctness
- [ ] critical-coverage

## Focused Fixer — Round 3
- [ ] fix focused round 3 findings
```

**Design decisions**:

- **`<!-- base_ref: ... -->`** on the first line stores the base ref used when the plan was generated. This ensures consistency across re-runs — if the user ran `dex review --from feature-x`, gets interrupted, then re-runs `dex review` without `--from`, the stored base_ref is used. The `plan.rs` parser ignores HTML comments (they're not headings or checkboxes). A simple line parser extracts the base_ref before plan.rs parsing.
- **One checkbox per reviewer** under each review heading. The checkbox text is the reviewer name (e.g., `quality`, `security`).
- **One checkbox per fixer** under each fixer heading. The text is descriptive (e.g., `fix broad review findings`).
- **All focused rounds are pre-generated** (1 through `MAX_FOCUSED_ROUNDS`). This lets us mark remaining rounds as skipped when an early round comes back clean.

### 2. `src/phases.rs` — `generate_review_plan()`

New function that creates `plan-review.md` from `reviewers.json`.

```rust
fn generate_review_plan(base_ref: &str, reviewers: &Reviewers) -> String {
    let mut lines = vec![format!("<!-- base_ref: {} -->", base_ref)];

    // Broad review
    lines.push(String::new());
    lines.push("## Broad Review".to_string());
    for rv in &reviewers.broad {
        lines.push(format!("- [ ] {}", rv.name));
    }

    // Broad fixer
    lines.push(String::new());
    lines.push("## Broad Fixer".to_string());
    lines.push("- [ ] fix broad review findings".to_string());

    // Focused rounds
    for round in 1..=MAX_FOCUSED_ROUNDS {
        lines.push(String::new());
        lines.push(format!(
            "## Focused Review — Round {}/{}",
            round, MAX_FOCUSED_ROUNDS
        ));
        for rv in &reviewers.focused {
            lines.push(format!("- [ ] {}", rv.name));
        }

        lines.push(String::new());
        lines.push(format!("## Focused Fixer — Round {}", round));
        lines.push("- [ ] fix focused round 1 findings".to_string());
    }

    lines.join("\n")
}
```

### 3. `src/phases.rs` — `read_review_plan_base_ref()`

Extracts the base_ref from the HTML comment on the first line of `plan-review.md`.

```rust
fn read_review_plan_base_ref() -> Option<String> {
    let content = read_dex_file("plan-review.md")?;
    let first_line = content.lines().next()?;
    let re = regex::Regex::new(r"^<!-- base_ref: (.+?) -->$").unwrap();
    re.captures(first_line).map(|caps| caps[1].to_string())
}
```

### 4. `src/phases.rs` — `mark_review_step_done()`

Marks a specific checkbox as done in `plan-review.md` by replacing `- [ ] <name>` with `- [x] <name>`.

```rust
fn mark_review_step_done(heading: &str, name: &str) {
    let Some(content) = read_dex_file("plan-review.md") else {
        return;
    };
    let re = regex::Regex::new(&format!(
        r"^(- \[) \](\s+{})$",
        regex::escape(name)
    )).unwrap();
    let updated: Vec<String> = content
        .lines()
        .map(|line| {
            if let Some(caps) = re.captures(line) {
                format!("- [x]{}", &caps[2])
            } else {
                line.to_string()
            }
        })
        .collect();
    let _ = fs::write(dex_path("plan-review.md"), updated.join("\n"));
}
```

**Note**: This replaces the first `- [ ] <name>` match globally. Since reviewer names are unique across the plan (broad and focused reviewers have different names per the existing test `focused_reviewer_names_do_not_overlap_with_broad_reviewers`), this is safe. Fixer step names include the round number (e.g., `fix focused round 1 findings`), so they're also unique.

### 5. `src/phases.rs` — `mark_remaining_skipped()`

Marks all remaining unchecked checkboxes as skipped with a note. Used when a focused round comes back clean — all subsequent rounds are unnecessary.

```rust
fn mark_remaining_skipped(plan_path: &str, note: &str) {
    let Some(content) = read_dex_file("plan-review.md") else {
        return;
    };
    let re = regex::Regex::new(r"^(- \[) \](\s+.+)$").unwrap();
    let updated: Vec<String> = content
        .lines()
        .map(|line| {
            if let Some(caps) = re.captures(line) {
                format!("- [x]{} ({})", &caps[2], note)
            } else {
                line.to_string()
            }
        })
        .collect();
    let _ = fs::write(dex_path("plan-review.md"), updated.join("\n"));
}
```

### 6. `src/phases.rs` — `review_phase()` rewrite

The main review phase function is rewritten to use `plan-review.md`.

```rust
pub fn review_phase(
    r: &Runner,
    plan_path: &str,
    base_ref: &str,
    parallel: Option<usize>,
    force: bool,
) -> Result<(), String> {
    let reviewers = {
        let path = dex_path("reviewers.json");
        match fs::read_to_string(&path) {
            Ok(data) => serde_json::from_str(&data).unwrap_or_else(|_| {
                warn("Invalid .dex/reviewers.json, falling back to defaults.");
                Reviewers::builtin()
            }),
            Err(_) => Reviewers::builtin(),
        }
    };

    let review_plan_path = dex_path("plan-review.md");

    // Load or generate review plan
    if force || !PathBuf::from(&review_plan_path).exists() {
        // Fresh start: delete existing review artifacts
        for entry in fs::read_dir(DEX_DIR).unwrap_or_else(|_| {
            fs::create_dir_all(DEX_DIR).ok();
            fs::read_dir(DEX_DIR).unwrap_or_else(|_| panic!("cannot create .dex dir"))
        }).flatten() {
            let name = entry.file_name().to_string_lossy().to_string();
            if name.starts_with("review-") && name.ends_with(".md") {
                remove_dex_file(&name);
            }
        }

        let plan_content = generate_review_plan(base_ref, &reviewers);
        ensure_dex_dir();
        fs::write(&review_plan_path, &plan_content)
            .map_err(|e| format!("write plan-review.md: {}", e))?;
    } else {
        // Existing plan — check if reviewers.json changed
        let existing_plan = read_dex_file("plan-review.md").unwrap_or_default();
        let expected = generate_review_plan(
            read_review_plan_base_ref().as_deref().unwrap_or(base_ref),
            &reviewers,
        );
        // Compare checkbox names only (ignore checked state)
        if !plans_have_same_structure(&existing_plan, &expected) {
            warn("reviewers.json changed since plan-review.md was generated. Use --force to regenerate.");
        }
    }

    // Use stored base_ref if available
    let effective_base_ref = read_review_plan_base_ref()
        .unwrap_or_else(|| base_ref.to_string());

    // Walk through the plan, executing each incomplete step
    loop {
        let Some(task) = next_open_task(&review_plan_path)? else {
            info("All review steps complete!");
            return Ok(());
        };

        let header = task.header.trim().trim_start_matches('#').trim();

        if header.starts_with("Broad Review") {
            run_broad_review_step(r, plan_path, &effective_base_ref, &task, parallel)?;
        } else if header.starts_with("Broad Fixer") {
            run_broad_fixer_step(r, plan_path, &effective_base_ref, &task)?;
        } else if header.starts_with("Focused Review") {
            let all_clean = run_focused_review_step(r, plan_path, &effective_base_ref, &task, parallel)?;
            if all_clean {
                mark_remaining_skipped(&review_plan_path, "skipped — prior round clean");
                info("All focused reviewers report ZERO ISSUES. Review phase complete!");
                return Ok(());
            }
        } else if header.starts_with("Focused Fixer") {
            run_focused_fixer_step(r, plan_path, &effective_base_ref, &task)?;
        }
    }
}
```

**Key behavior**:

- **No `--resume` flag**: Re-running `dex review` always reads the existing `plan-review.md` and continues from the first open checkbox. This matches how `dex apply` works — no special flag needed.
- **`--force` flag**: Deletes all `review-*.md` files and regenerates `plan-review.md` from scratch.
- **Early exit**: When a focused round comes back clean, `mark_remaining_skipped()` marks all remaining checkboxes as `[x] (skipped — prior round clean)` and returns.
- **Base ref consistency**: The stored `base_ref` is used on re-runs, ensuring the diff doesn't change between invocations.

### 7. `src/phases.rs` — Step execution functions

Each step type has a dedicated function that:
1. Runs the appropriate reviewers or fixer
2. Marks completed checkboxes in `plan-review.md`

#### `run_broad_review_step()`

```rust
fn run_broad_review_step(
    r: &Runner,
    plan_path: &str,
    base_ref: &str,
    task: &TaskGroup,
    parallel: Option<usize>,
) -> Result<(), String> {
    // task.body() contains the checkbox lines like "- [ ] quality\n- [ ] security"
    // Extract reviewer names from unchecked items
    let names = extract_open_names(task);
    let reviewers_to_run: Vec<&ReviewRole> = names.iter()
        .filter_map(|name| reviewers.broad.iter().find(|rv| rv.name == *name))
        .collect();

    run_review_fanout(r, plan_path, base_ref, &reviewers_to_run, "broad", 1, 1, parallel)?;

    // Mark each completed reviewer
    for name in &names {
        mark_review_step_done("Broad Review", name);
    }
    Ok(())
}
```

#### `run_broad_fixer_step()`

```rust
fn run_broad_fixer_step(
    r: &Runner,
    plan_path: &str,
    base_ref: &str,
    task: &TaskGroup,
) -> Result<(), String> {
    let names = extract_open_names(task);
    if names.is_empty() {
        return Ok(());
    }

    // Collect issues from broad review files
    let issues = collect_issues_from_reviewers(&reviewers.broad);
    match issues {
        None => {
            // No issues found — auto-check with note
            mark_review_step_done("Broad Fixer", "fix broad review findings (skipped — no issues found)");
            Ok(())
        }
        Some(ref issues) => {
            run_fixer(r, plan_path, base_ref, issues)?;
            mark_review_step_done("Broad Fixer", "fix broad review findings");
            Ok(())
        }
    }
}
```

#### `run_focused_review_step()`

```rust
fn run_focused_review_step(
    r: &Runner,
    plan_path: &str,
    base_ref: &str,
    task: &TaskGroup,
    parallel: Option<usize>,
) -> Result<bool, String> {
    let names = extract_open_names(task);
    let reviewers_to_run: Vec<&ReviewRole> = names.iter()
        .filter_map(|name| reviewers.focused.iter().find(|rv| rv.name == *name))
        .collect();

    let issues = run_review_fanout(r, plan_path, base_ref, &reviewers_to_run, "focused", round, MAX_FOCUSED_ROUNDS, parallel)?;

    // Mark each completed reviewer
    for name in &names {
        mark_review_step_done(&task.header, name);
    }

    Ok(issues.is_none())
}
```

#### `run_focused_fixer_step()`

### 8. `src/phases.rs` — `extract_open_names()`

Extracts reviewer names from unchecked checkboxes in a `TaskGroup`.

```rust
fn extract_open_names(task: &TaskGroup) -> Vec<String> {
    let re = regex::Regex::new(r"^-\s+\[\s\]\s+(.+)$").unwrap();
    task.lines
        .iter()
        .filter_map(|line| {
            re.captures(line).map(|caps| caps[1].trim().to_string())
        })
        .collect()
}
```

### 9. `src/phases.rs` — `collect_issues_from_reviewers()`

Re-reads existing `review-<name>.md` files for a set of reviewers and returns issues in the same format as `run_review_fanout`. Needed when the fixer step runs after reviewers have already completed (their output files exist but the fixer hasn't run yet).

```rust
fn collect_issues_from_reviewers(reviewers: &[ReviewRole]) -> Option<Vec<String>> {
    let mut all_clean = true;
    let mut issues = Vec::new();
    let clean_review_re = regex::Regex::new(r"(?i)[-*]\s*(zero|no)\s+(findings|issues)").unwrap();

    for rv in reviewers {
        let review = read_dex_file(&format!("review-{}.md", rv.name));
        match review {
            None => {
                all_clean = false;
            }
            Some(review) => {
                if clean_review_re.is_match(&review) {
                    // clean
                } else {
                    all_clean = false;
                    issues.push(format!("\u{2500}\u{2500} {} \u{2500}\u{2500}\n{}", rv.name, review));
                }
            }
        }
    }

    if all_clean { None } else { Some(issues) }
}
```

**Dispatch logic** (`main.rs`):

```rust
SubCommand::Review(cmd) => {
    let plan_path = require_plan_exists()?;

    let base_ref = match impl_commits_base_ref() {
        Some(r) => r,
        None => match cmd.from {
            Some(r) => {
                git_trimmed_output(&["rev-parse", "--verify", &r]).map_err(|e| {
                    CmdError::Failure(format!("invalid --from ref {:?}: {}", r, e))
                })?;
                r
            }
            None => {
                return Err(CmdError::Failure(
                    "No implementation history found. Run `dex apply` first, or pass `--from <base-ref>` explicitly.".into(),
                ));
            }
        },
    };

    review_phase(&runner, &plan_path, &base_ref, cmd.parallel, cmd.force)?;
    finish("Review complete.");
    Ok(())
}
```

### 13. `src/phases.rs` — `plans_have_same_structure()`

Compares two plan strings to check if they have the same checkbox names (ignoring checked state). Used to detect when `reviewers.json` has changed.

```rust
fn plans_have_same_structure(a: &str, b: &str) -> bool {
    let checkbox_re = regex::Regex::new(r"^-\s+\[[ xX]\]\s+(.+)$").unwrap();
    let heading_re = regex::Regex::new(r"^#{1,6}\s+.*$").unwrap();

    fn extract_structure(content: &str) -> Vec<(String, Vec<String>)> {
        let mut sections: Vec<(String, Vec<String>)> = Vec::new();
        let mut cur_heading = String::new();
        let mut cur_names: Vec<String> = Vec::new();

        for line in content.lines() {
            if heading_re.is_match(line.trim()) {
                if !cur_names.is_empty() || !cur_heading.is_empty() {
                    sections.push((cur_heading.clone(), cur_names.clone()));
                }
                cur_heading = line.trim().to_string();
                cur_names.clear();
                continue;
            }
            if let Some(caps) = checkbox_re.captures(line) {
                cur_names.push(caps[1].trim().to_string());
            }
        }
        if !cur_names.is_empty() || !cur_heading.is_empty() {
            sections.push((cur_heading, cur_names));
        }
        sections
    }

    extract_structure(a) == extract_structure(b)
}
```

## What NOT to do

- **Don't add `--resume` flag** — re-running `dex review` always resumes from the plan. No special flag needed, matching how `dex apply` works.
- **Don't add session tracking or resume** — too complex for the benefit. The plan-based approach handles the "skip completed work" case without needing to resume agent sessions.
- **Don't extend retry count** — out of scope for this change. The retry schedule can be adjusted independently.
- **Don't add fixer annotations to review files** — the plan checkboxes already track what's done. Review files stay as pure reviewer output.
- **Don't validate review file completeness** — there's no reliable way to tell if a `review-<name>.md` is complete vs. partial. The checkbox is the source of truth: if it's checked, the step is done.
- **Don't auto-regenerate the plan when reviewers.json changes** — just warn. The user can use `--force` to regenerate. Auto-regeneration risks losing progress information.

## Edge Cases

### Stale review files after fixer commits

After the fixer commits fixes, broad review files may review code that no longer exists. This is acceptable because:
- Focused review rounds re-review the updated code
- Stale broad reviews are still useful as context
- If the user wants fully fresh reviews, they can use `--force`

### Partial reviewer output

If a reviewer was interrupted mid-write, the file may be incomplete. Since the checkbox won't be checked (dex only checks it after successful completion), the reviewer re-runs on the next invocation. The incomplete file is overwritten.

### User edits `plan-review.md`

Users can manually check/uncheck steps, just like editing `plan.md` during `apply`. This is a feature — it gives users control over which steps to skip or re-run.

### `--from` changes between runs

If `plan-review.md` exists, the stored `base_ref` is used regardless of `--from`. This ensures consistency. To change the base ref, use `--force` to regenerate the plan.

### No issues found — fixer step

When all reviewers in a phase report zero issues, the fixer step is auto-checked with a note: `- [x] fix broad review findings (skipped — no issues found)`. This keeps the plan complete and self-documenting.

## Testing Plan

### Unit tests

1. **`generate_review_plan()`**: Verify output contains correct headings, checkboxes, and base_ref comment for a given `Reviewers` struct.

2. **`read_review_plan_base_ref()`**: Verify extraction from valid HTML comment. Verify returns `None` for missing/invalid comment.

3. **`extract_open_names()`**: Verify extracts names from `- [ ] name` lines. Verify ignores `- [x] name` lines. Verify ignores non-checkbox lines.

4. **`mark_review_step_done()`**: Verify `- [ ] quality` becomes `- [x] quality`. Verify other lines unchanged. Verify no-op if name not found.

5. **`mark_remaining_skipped()`**: Verify all `- [ ]` become `- [x] ... (skipped — note)`. Verify `- [x]` lines unchanged.

6. **`plans_have_same_structure()`**: Verify same headings + checkbox names → true. Verify different names → false. Verify ignores checked state.

7. **`collect_issues_from_reviewers()`**: Verify returns `None` when all reviews are clean. Verify returns issues when some reviews have findings. Verify handles missing review files.

### Integration tests

1. **Fresh review generates plan**: Run `dex review` with no existing `plan-review.md`. Verify plan is generated with correct structure.

2. **Re-run skips completed steps**: Create `plan-review.md` with broad review checkboxes checked. Run `dex review`. Verify broad reviewers are not invoked. Verify focused round 1 runs.

3. **`--force` regenerates**: Create `plan-review.md` with some steps checked. Run `dex review --force`. Verify plan is regenerated fresh (all unchecked) and all `review-*.md` files are deleted.

4. **Early exit on clean focused round**: Create plan with focused round 1 reviewers checked. Run `dex review`. If focused round 1 is clean, verify remaining rounds are marked skipped.

5. **Fixer skipped when no issues**: All broad reviewers report zero issues. Verify fixer checkbox is auto-checked with `(skipped — no issues found)`.

6. **Base ref consistency**: Generate plan with `--from feature-x`. Re-run without `--from`. Verify the stored base_ref is used (not the default from `impl_commits.jsonl`).

7. **Reviewers.json change warning**: Generate plan. Modify `reviewers.json`. Run `dex review`. Verify warning is printed but plan is not regenerated.

### Manual testing

1. **Interrupt and resume**: Run `dex review`. Kill dex mid-broad-review. Re-run `dex review`. Verify it continues from where it left off (completed reviewers are skipped).

2. **Interrupt and resume mid-fixer**: Run `dex review`. Kill dex after broad review but before fixer completes. Re-run `dex review`. Verify fixer re-runs (its checkbox is unchecked).

3. **Full cycle**: Run `dex review` to completion. Verify all checkboxes are checked. Re-run `dex review`. Verify it immediately reports "All review steps complete!"
